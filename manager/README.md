# PIP POPPER 管理ツール Version 1 — 操作説明と仕様

公式サイトの**文字情報**（曲名・歌詞・紹介文・制作秘話・サイトの文言）を、AIやコマンドを使わずに直して公開・取り消しするための道具。このパソコンの中だけで動く。

## 使い方（Producer）

### 第1〜第3段階の試作品を確認する（本番に接続しない）

正式フォルダー直下の **`PIP POPPER試作品プレビューを起動.bat`** をダブルクリック。開いた案内画面からPRIVATE鑑賞画面・管理ツール（PC／スマホ幅）を選ぶ。入室 `preview-member`、管理者 `preview-admin` は架空データ用のみ。実際のパスワードは入力しない。

- 30曲の架空曲名、歌詞、ジャケット、合成試聴音（WAV）。第1〜第3段階の実際の画面コード・Workerの保存処理を使用するが、R2はメモリ内の模擬データ、公開状況記録は `.manager/prototype-preview/run-.../` 内の試作品専用記録。実音源・実楽曲・既存管理記録とは完全に分離。
- 歌詞を編集・保存したらPRIVATEページを再読み込みすると変更が表示される。公開状況の絞り込み、区分・歌詞範囲・URL編集も試せる。外部配信URLは架空。外部フォント読み込みを行わずPC内の代替フォントを使用。
- スマホ幅ボタンが開かない場合はブラウザのF12 → Ctrl+Shift+M → 幅390px。案内画面の「試作品を終了」か管理ツールの右上「終了」で停止。黒い画面も閉じる。再起動すると架空データは初期状態に戻る。
- 本番公開、パスワード変更、通常楽曲データ変更は試作品側で拒否。検証：`PIP POPPER試作品プレビューを起動.bat --check`（BAT実行、模擬Worker、保存、拒否、localhost待受け確認）。実ブラウザの操作確認はProducerのPCで実施する。

### 通常の管理ツール（正式運用用）

1. エクスプローラーで `AI作業\PIP POPPER公式サイト\` を開き、**`PIP POPPER管理ツール.exe`** をダブルクリック。
   既定のブラウザに管理画面が開く。実行中のEXEは右上の「終了」を押すまで管理サーバーを保持する。再度EXEを開くと同じサーバーの画面が開く。
2. 左の一覧から直したいものを選ぶ（楽曲／HISTORY（アルバム）／その他の作品／サイトの文言。上の欄で名前をさがせる）。
3. 文字を直して **保存**。この時点ではまだ公開されない（一覧に ● が付き、上部に「公開していない変更が○件」と出る）。
4. **プレビュー** で、実際のページと同じ見た目を確認する（新しいタブで開く）。
5. よければ上の **公開する** → 確認画面で、公開先と「前 → 後」の一覧を見て **公開する**。1〜3分で https://pip-popper.github.io/ に反映（Ctrl＋F5 で再読み込み）。
6. 元に戻したいとき
   - 公開前：**変更を破棄**（最後に公開した状態に戻る）
   - 公開後：**公開履歴・取り消し** → その公開の **取り消す** → 「公開していない変更」に入るので、プレビューで確認して **公開する**
7. 終わったら画面右上の **終了**。管理サーバーとEXEが終了する。

### PRIVATEのパスワードを変える（PRIVATE管理）
1. 左の一覧の「PRIVATE管理」→「PRIVATEのパスワード」。
2. 「新しいパスワード」（8〜200文字、前後に空白なし、管理者パスワードとは別）と「確認用」を入力。
3. 「管理者パスワード」（PRIVATEの管理画面に入るときのパスワード）を入力して「パスワードを変更」→ 確認で「変更する」。
4. 「✔ 変更が完了しました」と出れば完了。**すぐに反映**され、入室中の招待者は全員、新しいパスワードで入り直しになる（音源・曲目は変わらない）。新しいパスワードを招待者に伝える。
- 入力したパスワードは処理が終わると画面から消え、パソコンにも記録にも残らない。
- 管理者パスワードを10分に5回間違えると60分ロック。変更・戻す操作は全体で1時間に10回まで。
- 「以前のパスワード（Cloudflareに登録したもの）に戻す」は通常使わない。確認の言葉「旧パスワードに戻す」と管理者パスワードが必要。
- 「PRIVATE側がまだこの機能に対応していません」と出たら、Cloudflareの更新（担当者の作業）がまだ。パスワードは変わっていない。
- 管理者パスワード自体の変更は、これまでどおりCloudflareのダッシュボード（保守マニュアル3-2）。

### PRIVATE楽曲の歌詞・よみがなを登録・編集する（ローカル実装・本番未反映）

1. 左の「PRIVATE管理」→「PRIVATE楽曲の歌詞・よみがな」を選ぶ。
2. 管理者パスワードを入力し「PRIVATE曲一覧を読み込む」。曲名とID・歌詞の登録状態を確認して選曲。
3. PRIVATE専用歌詞を入力・編集（改行・空行を保持）。既に一般公開済みの歌詞は公式サイト側で管理し、同じ歌詞を重複登録しない。公式サイトの既存作品へのリンクから確認できる。
4. 管理者パスワードを再入力して「内容を確認して保存」。対象曲名・ID・全文・PRIVATEへ直ちに反映する旨を確認して「保存する」。音源の再登録は不要。
5. 保存結果が表示される。別の端末で変更されていた場合や保存失敗時は入力を保持し、勝手に上書きしない。必要なら入力を控えて一覧を再読込みする。

漢字などの曲は「曲名のよみがな」に必要な読みを入力して保存する（ひらがな・カタカナ・英数字、100文字以内）。空欄でも曲名から自動整列し、読み未設定の漢字から始まる曲は末尾のグループで表示。順序は かな→英字A–Z→数字（自然順）→その他。読みだけ変更した場合は歌詞を上書きしない。PRIVATE鑑賞画面を再読み込みすると新しい表示順を確認できる。登録順・音源・公開サイトは変わらない。

歌詞は管理者認証済みWorkerが非公開R2の曲目に保存する。GitHub・ローカルの公開曲データ・音源には書き込まない。管理者パスワードは毎回処理終了前に入力欄から消去し、歌詞もパスワードもログに残さない。EXEの構成は変更せず、既存ランチャーが起動するサーバーと画面を更新した。実ブラウザ・ローカルHTTP結合は権限制限のため未検証、Cloudflareデプロイ・本番R2書込みは別途承認後。

### 全楽曲の公開状況（第3段階、ローカル実装）

1. 左の「楽曲公開状況」→「全楽曲の公開状況」を選ぶ。初期表示は公式サイトのローカル資料と保存済み管理記録。
2. 管理者パスワードを入力して「PRIVATE曲一覧も読み込む」。同じ曲IDは1件に統合され、PRIVATEの曲も含めて集計する。取得前の件数は全曲の確定数ではない。
3. 「すべて／一般公開／このサイトのみ／PRIVATEのみ／未設定・要確認」で絞り込み、曲名・曲IDで検索。未設定は自動分類しない。
4. 曲を選び、公開区分・歌詞の公開範囲を独立して設定する。配信先名と確認済みのhttps URLを追加・編集できる。公式サイトの既存ソース登録URLが初期値。未確認URLを追加しない。
5. 「確認して管理情報を保存」で対象曲・区分・配信先を確認。保存は管理記録のみ。公式サイト、PRIVATEの音源・歌詞、外部配信サービスへの変更は一切行わない。確認できた掲載や歌詞と指定が異なる場合は警告を表示する。

管理記録の正本は `.manager/release-status.json`（設定に変更がない間は作成しない）、前の版は `.manager/release-status-backups/`。曲IDをキーに保存、古い画面からの上書きは拒否。これらはPRIVATE情報を含み得るためGit・公開ページ・プレビューへ入れず、非公開の保守対象として保護する。パスワード・歌詞本文は記録しない。実際の公開状態と管理上の指定は別で、外部配信の稼働確認は未実施。公開サイト側の通常の配信リンク編集機能は従来どおり。

### 新曲掲載登録（2026-11-23、ローカル候補）

1. 左の「新曲掲載準備」→「＋ 新曲を登録」。曲名、任意のよみがな、アーティスト（既定PIP POPPER）、歌詞、AIの感想を入力する。生成はChatGPT側で行い、管理ツールには生成機能を持たせない。
2. ジャケットのPNG/JPEG（12MB以内）を選択。登録前に画像が見える。原画像を保持し、既存サイト互換の `cover-web.jpg`（最大幅1254）・`cover-640.jpg`（幅640）をブラウザで作成する。縦横比を維持。画像がなくても下書き保存できる。
3. 公開区分、歌詞・AIの感想の個別公開範囲、3掲載先の許可、URL、公開メモ、登録状態を入力。PRIVATEのみ・未設定は一般公開HP/一般視聴を選べない。公開準備完了には画像・公開区分・掲載先が必要。実際の公開・音源登録は常に未実施表示（公開済みは実際の反映検証後の統合工程でのみ設定）。
4. 「確認して保存」で曲IDを自動発行。登録中の曲が左の一覧と「全楽曲の公開状況」に出る。編集・画像差替えは同じIDで保存。古い画面の保存は拒否。保存履歴から過去版を復元でき、現在版も残る。
5. 保存後「掲載イメージ」で一般公開HP／一般視聴／PRIVATEとPC／スマホ相当を切替。許可のない情報は出ない。音源は未登録であることを表示し、再生ボタンは無効。掲載候補の個別プレビューであり、正式公開ページへの反映そのものではない。

保存先は `.manager/song-registrations/<曲ID>/versions/<保存版>/`（Git対象外）の `record.json`、原画像、表示用JPG。`current.json` が正式な現在版を指す。公開準備完了かつ該当掲載先を許可すると、正式統合に使う限定データを同じ非公開保存版へ用意する：`public-candidate/track.json` と表示用JPG、`public-listening-candidate.json`（音源承認false・キー未設定）、`private-candidate.json`。管理メモ・制限付き歌詞/感想を公開候補に入れない。公開候補もこの段階ではGit・公開ソース・R2に移さない。復元・更新は現在版だけを統合対象とする。

**試作品確認：** 同じ `PIP POPPER試作品プレビューを起動.bat` → 管理ツール → 新曲を登録。試作品専用フォルダーに保存され、再起動で新しい試作品となるため、実運用の原本登録には通常管理ツールを使用する。実ブラウザでのファイル選択/表示はProducer確認待ち。模擬検証 `node manager/test-song-registration.mjs`、`node manager/test-release-status.mjs`、`node private/dev/test-library.mjs`、`node public-listening/test.mjs`、BAT `--check` 合格。

**新曲を公式HPに載せるまで（2026-11-24 正式統合、Claude Code）：**

1. 「＋ 新曲を登録」で入力・画像選択 →「確認して保存」（下書き。何度でも保存でき、保存履歴から復元できる）。
2. 公開してよい内容になったら、公開区分（一般公開／このサイトのみ）、歌詞・AIの感想の公開範囲（一般公開）、「一般公開HPへの掲載を許可」を設定し、登録状態を「公開準備完了」にして保存。「掲載イメージを見る」で確認。
3. 同じ画面の下「公式HPへの取り込み」で、ページのURL名（英小文字・数字・ハイフン、例 `we-love-music`。公開後は変えない）を入れて「公式HPの掲載データへ取り込む」。承認済みの公開項目と表示用画像2枚だけが `tracks/<URL名>/` に入る（管理メモ・非公開の歌詞や感想は入らない）。**まだ公開されない。**
4. 画面上部の「プレビュー」で確認 →「公開する」（確認画面に新曲の項目と画像が並ぶ）。押したときだけ公式サイトへ送信される。公開前なら「変更を破棄」で取り込みを取り消せる。公開後は「公開履歴・取り消し」で取り消せる。
5. 登録画面の「実際の公開」は自動で決まる：未取り込み → 取り込み済み（未公開）→ 公開済み（GitHubにある時だけ）。手で「公開済み」にはできない。
6. 取り込んだ後の文字の修正は、左の「曲」の一覧から（通常の曲と同じ）。よみがな（あいうえお順用）も曲の編集画面で入力できる。

音源について：公式HPには音源を置かない（従来どおり）。PRIVATEで聴けるようにするには、PRIVATE管理画面 `/admin` の「曲を追加」で音源をアップロード（公開済みの曲は一覧から選べる）し、歌詞は「PRIVATE楽曲の歌詞・よみがな」から登録する。一般視聴ページへの掲載は、一般視聴の本番環境（独立Worker・専用R2）をProducer承認で用意した後（`public-listening/README.md`）。

### 画面の配置（2026-11-24）

左上の **管理メニュー**（いつも見える）：新曲を登録／アルバムを登録／下書き・登録中の曲とアルバム／楽曲の公開状況／PRIVATE音源の登録・管理（PRIVATE の管理画面を別のタブで開く）／PRIVATE歌詞・よみがな／PRIVATEパスワード／公開履歴・取り消し／（あるときだけ）削除済み・一覧から外したもの。
その下が **曲・アルバム・ページの一覧**（見出しごとに折りたたみ、メニューとは別にスクロール。検索すると該当する見出しが開く）。
新曲の登録状態は「下書き」「公開準備完了」の2つ。「公開済み」は実際の公開状態から自動表示（以前の「登録済み」は効果がなかったため廃止し、残っていても下書きとして表示）。

### 一般視聴の管理（2026-11-25）

公式サイトのメニュー「LISTEN｜音楽を聴く」から誰でも（パスワードなしで）聴けるページ（PRIVATE Worker の `/listen/`）に載せる曲を、管理ツールだけで扱う。
1. 管理メニュー「一般視聴の管理」→ 管理者パスワード（PRIVATE の管理画面のもの）→「読み込む」。公式サイトの曲（音源非公開の曲を除く）が並ぶ。
2. 曲を選ぶ →「MP3を選ぶ」（選ぶとその場で試聴できる。短縮版・編集版も可、50MBまで）→「この音源を登録（まだ公開しない）」。PRIVATE の完全版を使うときは「PRIVATEの音源をコピーして使う」（対象の曲名を確認する画面が出る。PRIVATE は変わらない）。
3. 「歌詞」「ジャケット」「AIの感想」を出すかを選んで「公開する項目を保存」（中身は公式サイトの曲のもの）。
4. 「公開前の音源を試聴」→「内容を確認して公開する」（曲名・MP3の大きさ・再生時間・公開する項目を確認）。公開すると画面と件数がその場で更新される。
5. 差し替え：新しいMP3を登録すると「公開前の版」になり、公開中は前の音源のまま。「公開する」で入れ替わり、前の版は履歴に残る。
6. 「掲載を停止する」「掲載を再開する」「以前の版に戻す（下書きへ）」「一般視聴の一覧から外す／一覧に戻す」。音源ファイルは消さない。
- 仕組み：管理ツール → PRIVATE Worker の管理API（`/admin/api/listen/...`、管理者の入室が必要）→ 既存R2。公開用の音源は `public-audio/`、管理記録 `public-manage.json`（一般からは読めない）、公開カタログ `public-catalog.json`（公開した曲だけ）。新しいWorker・R2・費用なし。音源は GitHub に置かない。
- 公開曲が0曲のときは、一般視聴ページに「準備中」の案内が出る。

### 持ち運び用一式（2026-11-24）

`C:\PRODUCER SSD\PRODUCER OFFICE\AI作業\PIP POPPER管理ツール一式\` に、EXE・同梱の Node.js と Git（`manager\runtime`）・サイトの原本と公開履歴（Git）・管理データ（`.manager`：新曲とアルバムの登録、保存前の控え、一覧から外したもの）をまとめた。フォルダーを丸ごとコピーして EXE をダブルクリックするだけで使える（中の「はじめにお読みください.txt」）。
- 作り方：正式リポジトリを clone → 送信先を GitHub に設定 → リポジトリ内に Git の名前（Producer／producer@local）と改行設定を記録 → EXE・`manager\runtime`・`.manager` の必要なもの（song-registrations・album-registrations・backup・archived.json・release-status.json）をコピー。試作品・引継ぎパッケージ・プレビュー等の開発用ファイルは入れない。
- 移動に対応：Git が別ドライブで所有者を理由に拒否しないよう、そのフォルダーだけを信頼する設定で動く。起動時、公開していない変更も未送信の保存点もないときだけ、GitHub の新しい公開内容を早送りで取り込む（複数のコピーが食い違わないため）。
- 新しいパソコン：インストール不要。最初の「公開する」で GitHub のサインイン（資格情報は Windows に保存され、フォルダーには入らない）。
- 注意：管理データ（下書き・保存履歴）はそれぞれのコピーにしかない。Producer は一式だけを使い、正式プロジェクトの EXE は使わない。

### アルバムを載せるまで（2026-11-24）

1. 「＋ アルバムを登録」で、アルバム名・掲載ページ（HISTORY／その他の作品）・区分・年・公開日の表示・ジャケット（PNG/JPEG）・紹介文・制作秘話（空行で段落）・収録曲を入れる。収録曲は「追加」で公式サイトの曲を選ぶ（曲ページへのリンクが付く）か、曲名だけを入れる。↑↓で曲順、「外す」で曲目から外す（曲そのものは消えない）。
2. 「確認して保存」（下書き）。何度でも保存でき、「保存履歴・復元」で前の版に戻せる。不要な登録は「この登録を削除」（左の「削除済み・一覧から外したもの」から戻せる）。
3. 載せてよくなったら登録状態を「公開準備完了」にして保存 →「公式HPのアルバムデータへ取り込む」（ページのURL名を英小文字で決める）。アルバムはそのページの最後に加わる。
4. 左の一覧で作品を開き「プレビュー」→「公開する」。新しいアルバムは、ジャケット・紹介文（「アルバム紹介」）・制作秘話・作品情報・収録曲の標準の形で表示される（既存作品の特設デザインは変わらない）。
5. 取り込んだ後は、作品の編集画面で文字・掲載順・収録曲・ジャケットを変えられる。

### 掲載をやめる・戻す（2026-11-24）

- 曲・作品の編集画面の「掲載の管理」→「掲載を停止する」→ 公開。公式サイトからそのページ・一覧・画像が消える（アルバムの曲目では曲名だけ残りリンクが外れる）。データ・画像・PRIVATE は消えない。
- 戻すときは「掲載を再開する」→ 公開。
- 掲載停止中のものは「管理一覧から外す」で左の一覧から隠せる。「削除済み・一覧から外したもの」→「戻す」で一覧に戻る。
- 音源やデータの完全な削除はこの画面ではしない（必要なら Producer の承認を得て担当AIが行う）。

### 例：曲名「Showtime.com」を「Showtime2010」にする
HISTORY（アルバム）→ 該当アルバム → 「収録曲 › n › 曲名」を書き換え → 保存 → プレビュー → 公開する。

### うまくいかないとき
| 表示 | 意味と対応 |
|---|---|
| このデータは画面を開いた後に変更されています | 別の画面やAIの作業で先に変わった。左の一覧から選び直してから入力し直す |
| 管理ツール以外の変更が○件あります | AI等が作業中。作業が終わるまで公開しない（担当者に確認） |
| GitHub側に、このパソコンにない新しい変更があります | 別の場所で公開された。担当者に連絡 |
| GitHubへの送信に失敗しました | 変更は保存点として残っている。インターネット接続を確認し、もう一度「公開する」（送信だけやり直す） |
| 管理ツールはすでに起動しています | 前に開いたブラウザのタブを使う。見つからなければ黒い画面を閉じて起動し直す |

## できること・できないこと（v1）

- できる：既存の曲・アルバム・ページの**文字の値**の編集、保存、プレビュー、公開、公開の取り消し、未公開の変更の破棄、公開履歴の確認。
- できない（v1）：曲やアルバムの追加・削除、項目の追加・削除、並べ替え、画像の差し替え、デザインの変更、PRIVATE（音源）の操作、パスワードの変更。
- 取り消せるのは**管理ツールで公開した変更**だけ。AI等の作業による変更は対象外。

## 仕様（担当者・AI向け）

### Windows EXE起動

- 日常の入口：プロジェクト直下の `PIP POPPER管理ツール.exe`（Windows x64、.NET Framework 4系の小さなランチャー）。
- 同梱：`manager/runtime/node.exe` と `manager/runtime/git/`。EXEはこのNodeを直接起動し、子プロセスのPATHに同梱Gitを設定する。Node・Gitのインストールは不要。GitHubへの送信には移動先PCのGit認証とインターネット接続が必要。
- コピーする単位はプロジェクト全体（隠しフォルダ `.git` と `.manager`、画像・データ・ソース・runtimeを含む）。EXEの位置を基準に起動する。
- 127.0.0.1の空きポートをOSに割り当ててもらうため、他のアプリが18990を使っていても起動できる。APIのHost・token確認は維持。
- フォルダごとの名前付きMutexとイベントで重複起動を防ぎ、起動済みなら既定ブラウザで同じ画面を開く。tokenはランチャーとサーバーのメモリ内だけに保持する。
- 「終了」でサーバーが終了するとEXEも終了する。EXEが異常終了した場合も、EXE所有の標準入力パイプが閉じると専用サーバーが終了する。
- 復旧用BATは保管。BATとEXEを同時に使わず、通常はEXEを使用する。
- EXEの再ビルド：PowerShellで `./manager/build-launcher.ps1`。ソース `manager/Launcher.cs`。ビルドにはWindows付属の.NET Frameworkコンパイラを使用。
- runtimeとEXEはGit対象外のローカル成果物。ソースとビルド手順をGitで管理する。
- EXE検証：`node manager/test-launcher.mjs`。正式フォルダと日本語・空白を含むコピー先を使い、ブラウザを開かずに起動・API・二重起動・終了を検証する。本番PRIVATEを呼ばない。

- 構成：`manager/server.mjs`（Node.js 標準機能のみ）＋ `manager/ui/`（画面）。起動は BAT → `node manager/server.mjs`。
- 待ち受け：`127.0.0.1:18990` のみ。起動ごとに合言葉（token）を作り、アドレスの `#t=` で画面に渡す。API は `X-PP-Token` と Host の一致が必要。POST は JSON のみ。
- 編集対象：`tracks/<ID>/track.json`（title・artist・aiImpression・lyrics・background）、`albums/albums.json`（各作品の文字の値。id・section・accent・visual・music・date・listOrder・archive・titleLines・backdrop は対象外）、`content/site.json`（全文言）。**値の書き換えだけ**で、項目の追加・削除・型の変更はしない。
- 保存：読み込み時の内容の指紋（rev）と一致するときだけ保存（上書き防止）。書式（字下げ・改行コード・末尾改行）を維持し、一時ファイル→置き換えで書く。保存前の内容は `.manager/backup/` に残す。
- プレビュー：`node build.mjs --out .manager/preview`（`docs/` は変えない）。
- 公開：ブランチ `main`・送信先 `origin`＝`https://github.com/pip-popper/pip-popper.github.io.git`・管理ツール以外の未保存変更なし・GitHub側が先に進んでいない、を確認 → `node build.mjs` → 変更ファイルが「データ＋docs」だけか確認 → `[管理ツール] …` の保存点（commit）→ `git push origin main:main`。GitHubの認証はこのパソコンに保存済みのGitの資格情報（管理ツールは秘密を持たない）。送信失敗時は保存点を残し、次の「公開する」で送信だけをやり直す。
- 取り消し：`[管理ツール]` の保存点で、データと docs だけを変えたものが対象。その保存点のデータの差分を逆に当てて「未公開の変更」にする（docs・GitHubは公開するまで変わらない）。後から同じ箇所が変わっていれば取り消さない。
- 破棄：変更されたデータファイルだけを最後の保存点の内容に戻す（戻す前の内容は `.manager/backup/` に残す）。
- 記録：`.manager/manager.log`（Git対象外）。PRIVATEの操作は「操作名と結果コード」だけを記録し、入力値は書かない。
- PRIVATEのパスワード：`POST /api/private/password`・`/api/private/restore`。サーバーが PRIVATE（`https://pip-popper-private.pip-popper-private.workers.dev/`）の `/admin/login` に管理者パスワードで入室（Webの管理画面と同じロック）→ `/admin/api/private-password`（または `/restore`）を呼ぶ（Worker側で管理者パスワードを再確認）→ `/admin/logout`。Cookieと入力値はこの1回の処理の中だけで使い、保存しない。CloudflareのAPIトークンは使わない。送信先は https のみ（テストでだけ `PP_MANAGER_PRIVATE_URL` に localhost を指定できる）。
- テスト：`node manager/test-manager.mjs`（一時フォルダーに検証用の送信先と作業コピーを作り、44項目を確認。本物のGitHub・作業フォルダーには触れない）。
- テスト用の設定（通常は使わない）：`--root`、`--port`、`--no-open`、環境変数 `PP_MANAGER_EXPECTED_REMOTE`・`PP_MANAGER_NO_OPEN`・`PP_MANAGER_PRINT_TOKEN`。
